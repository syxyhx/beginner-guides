## 读之前

- 需要：一个能用的邮箱、一台电脑。
- 要顺带申请学生福利的话，再多准备一样能证明在读的材料——学校邮箱（`.edu.cn` 等）、学生证照片、学信网在线验证报告，三选一即可。
- 不需要：任何编程基础，也不必会用命令行。
- 篇幅不大，但**不必从头读到尾**：正文第 8 页有一页「阅读路线：三种使用姿势」，按自己是「只用桌面端」「想认真学命令行」还是「手机应急为主」三条线之一走即可。第五章（二）那次「10 分钟第一次实操」是一条完整的端到端闭环，想先跑通一次可以直接从那里开始。

## 四条容易踩的坑

1. **按自己的使用方式跳读**。正文第 8 页的「阅读路线」给了三条线——A 只用桌面端（多数同学）、B 想认真学命令行、C 手机应急为主，各对应不同章节，从头硬读是浪费时间。
2. **提交身份别写真实姓名**。写进 `user.name` 的名字会永久留在每一次提交记录里，建议用网名或拼音缩写。
3. **桌面端自带的 Git 不等于系统 Git**。想用命令行必须另外装一份 git-scm.com 的，桌面端那份只给它自己用、没加进系统路径，在终端直接敲 `git` 会提示「不是内部或外部命令」。
4. **密码和访问令牌不是一回事**。GitHub 早已不支持用账号密码推送，走 HTTPS 要在 Settings → Developer settings 里生成 Personal Access Token 代替密码。

## 与另外两篇的关系

- **和 02、03 没有依赖关系**。01 用的是 GitHub 账号，02 和 03 用的是阿里云账号，两套体系互不相通，学生认证也各做各的——GitHub Education 认的是学校的在读证明，阿里云认的是支付宝里的学籍核验，两边都得单独走一遍。
- **唯一的衔接点是 GitHub 本身**：02 里如果有把配置或脚本存到仓库的习惯，才会用到这一篇的提交与推送；只部署服务的话，01 可以先不看。
