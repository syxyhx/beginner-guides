## 四条容易踩的坑

1. **端口放行不是「全开」**。1.4 与 4.11 的要求一致：管理端口绝不要对 `0.0.0.0/0` 开放。走 Tailscale 时 ufw 只放行组网网段 `100.64.0.0/10`（1.4 给了现成命令），确需临时直连就只填自己的公网 IP；连通性问题的排查口径见 4.11。
2. **别全程用 root 操作**。1.6 的五步初始化里第 4 步就是建一个日常用户并加 sudo，这一步不要跳过。
3. **进程会随 SSH 断开而死**。4.6 用进程守护解决，装完再关终端。
4. **远程访问只有两种可行方式**。4.7 按安全性排序给了两条：Tailscale 组网 ★★★★★ → Caddy 反代 + HTTPS ★★★★。「公网 IP + 端口直连」这条已从表中删除——dsh 对 `--host` 拒绝 `0.0.0.0` 这类通配地址，而云服务器的公网 IP 是 NAT 映射、网卡上并不存在，物理上绑不上。想用 IP 访问只能加一层反代，那就等价于 Caddy 方案。

## 与另外两篇的关系

- **不需要先读 01**。01 是 GitHub 账号，和云厂商账号是两套独立体系，学生认证也各做各的。
- **和 03 共用同一个阿里云账号，但接口默认不是百炼**。4.4 节主线走的是 **DeepSeek 官方 API**（默认端点 `https://api.deepseek.com/anthropic` + `deepseek-flash`）。想用 03 领的那张 300 元券，端点、模型、密钥三项必须一起改：

  - 端点 → `https://dashscope.aliyuncs.com/compatible-mode/v1`（Web 界面里改，或用环境变量 `DEEPSEEK_BASE_URL` 覆盖）
  - 模型 → 百炼控制台列出的模型名（qwen 系列），**不能沿用 `deepseek-flash`**
  - 密钥 → 03 里在百炼创建的那个 `sk-` 密钥，填在「设置 → Models」

  只换密钥、不改端点和模型名，一定报错。想少折腾就先做 03，再按上表改 4.4。

> 注意变量名：dsh 认的是 `DEEPSEEK_BASE_URL`，**没有** `LLM_API_KEY` / `LLM_MODEL` 这类统一变量。API Key 统一在 Web 界面里填，会存进 DSH_HOME 供所有 profile 复用。
